# Решения для API Gateway и Брокера Сообщений

## Задача 1: Выбор API Gateway

### Требования:
- Маршрутизация запросов
- Проверка аутентификации
- Терминация HTTPS
- 
### Сравнительная таблица API Gateway

| Решение       | Поддержка протоколов       | Маршрутизация | Аутентификация               | HTTPS | Балансировка | Логирование | Плагины/Расширения      | Сложность  | Производительность |
|---------------|----------------------------|---------------|-------------------------------|-------|--------------|-------------|-------------------------|------------|--------------------|
| **Kong**      | ✅ REST, gRPC, GraphQL     | ✅            | ✅ JWT, OAuth2                | ✅    | ✅           | ✅          | ✅ Lua-плагины          | Средняя    | Высокая            |
| **Envoy**     | ✅ REST, gRPC, SOAP        | ✅            | ✅ RBAC, JWT                  | ✅    | ✅           | ✅          | ✅ WASM-фильтры         | Высокая    | Очень высокая      |
| **Traefik**   | ✅ REST, GraphQL          | ✅            | 🟡 OIDC, Basic Auth           | ✅    | ✅           | ✅          | ✅ Middleware           | Низкая     | Высокая            |
| **Nginx**     | ✅ REST, SOAP             | ✅            | 🟡 Basic Auth, JWT (через Lua)| ✅    | ✅           | ✅          | 🟡 Требуется Lua        | Средняя    | Очень высокая      |
| **Tyk**       | ✅ REST, GraphQL          | ✅            | ✅ Многофакторная аутентификация| ✅   | ✅           | ✅          | ✅ Go-плагины           | Низкая     | Средняя            |
| **AWS API GW**| ✅ REST, WebSockets       | ✅            | ✅ IAM, Cognito               | ✅    | ✅           | ✅          | 🟡 Только облачные      | Низкая     | Высокая            |

### Выбор: **Kong**
**Обоснование:**
- Наибольшая гибкость (поддержка плагинов)
- Полноценная аутентификация
- Self-hosted решение
- Оптимален для микросервисов

Альтернативы:
- Traefik - для простых сценариев
- AWS API Gateway - для облачных решений

## Задача 2: Выбор Брокера Сообщений

### Требования:
- Кластеризация
- Сохранение на диск
- Высокая скорость
- Поддержка форматов
- Управление доступом
- Простота эксплуатации

### Сравнительная таблица Брокеров

| Решение       | Кластеризация  | Персистентность | Скорость | Форматы       | Права доступа | Управление       | Простота |
|---------------|----------------|-----------------|----------|---------------|---------------|------------------|----------|
| **RabbitMQ**  | ✅ (Mirrored)  | ✅              | 🟡       | ✅ (JSON и др) | ✅ (RBAC)     | Web UI, CLI      | ✅       |
| **Kafka**     | ✅ (ISR)       | ✅              | ✅       | ✅ (Avro и др) | ✅ (SASL)     | CLI, Tools       | 🔴       |
| **NATS**      | ✅ (JetStream) | ✅              | ✅       | ✅ (Text/JSON) | 🟡 (Basic)    | CLI, Monitoring  | ✅       |
| **Redis**     | ✅ (Sentinel)  | ❌              | ✅       | ✅ (Text/JSON) | 🟡 (Password) | CLI              | ✅       |
| **Pulsar**    | ✅ (BookKeeper)| ✅              | ✅       | ✅ (Protobuf)  | ✅ (TLS)      | Web UI, CLI      | 🟡       |

### Выбор: **RabbitMQ**
**Обоснование:**
- Оптимальный баланс надежности и простоты
- Полноценное сохранение сообщений
- Гибкая система прав доступа
- Удобный интерфейс управления

Альтернативы:
- Kafka - для high-load систем
- NATS - для ultra-low latency

---

## Итоговые рекомендации
1. **API Gateway**: Kong (для self-hosted) или AWS API Gateway (для облака)
2. **Брокер**: RabbitMQ (универсальный) или Kafka (для big data)
